# M10：统一 KV 遍历的训练、冻结与回归结果

数值与运行验证通过，性能规则未达到可全面采用的结果。统一单循环及分块/warp搜索，使T1024/4096相对M9首版少约11%–19% Graph耗时；但T256的冻结配置慢约4%–10%，并且统一候选仍落后强pack+FA2基线。因此这份policy保持实验用途，不能将训练收益称为可靠生产规则。

## 实验方法与冻结边界

新kernel用逻辑KV索引按三个段边界选择原始K/V指针，单循环处理四段，无cat/repeat KV。数学、BF16/FP32舍入、mask、owners/currentstream契约保持M9。跨段block及空段/tails独立验证。

固定12候选：token_tile16/32 × G1/2/4 × warps4/8，key64/stages2。seed1907，T96/384/1536 × selected256/1536，sink64/recent512/currentT，共6训练输入、72候选行。每候选先T65/history33/17/41及T0检查；全部通过，72训练行也全部正确，无资源失败。

选择只对原M9G1完整算子，用Graph paired p50：每candidate全部6输入正确，再在bucket两输入上geomean<=0.95、worst<=1.05，按最低geomean选择，index打破平局。small T<=128，medium<=512，large>512；不读取KV数据。初选同训练输入长复测，失败就回退，不试次优。小分组没有达到5%门槛，保留M9；中、大分组选同一候选11，并通过4个长复测输入。

训练Graph四轮AB/BA/BA/AB，每轮8样本、2replay/样本、8forward/replay；长复测改16样本、4replay。配置冻结后seed2917的12输入对照M9G1、冻结选择、复用buffer pack+未修改官方FA2。API和Graph四轮正/逆，8样本、2调用，Graph8forward；不计准备、oracle、hash、capture、telemetry。wall样本不是孤立host launch指标。

旧M8/M9矩阵的baseline与G对照已经已知；M10候选在新训练输入上选择，冻结后对照结果未参与选择，但这些不是完全未知workload。没有根据T256回归重选旧policy。

## 正确性、资源与证据

训练保存626项数值metrics，最大RMS 0.002264032、normalized max 0.002891292；冻结对照保存202项metrics（178 FP32、24 FA2比较），最大RMS 0.002279858、normalized max 0.004807692。全部finite且低于0.008，不放宽阈值。

两种唯一(mode,config)各跑12功能场景、两次原地Graph更新、非默认stream及恢复hash。12性能场景全部arm使用独立chunk64 FP32 oracle，TF32关闭，在API/Graph计时前后检查输出与输入hash。

## 判断与下一步

T256的规则转移失败：训练T384中获益的G4/warps8组合没有可靠覆盖较小的T256。仅以分桶阈值套用训练赢家会产生回归。更少register或spill也不直接证明更低延迟，当前没有硬件计数器来确认原因。

首版T64 fallback仍比强FA2链路快约5%–29%；T1024/4096统一候选相对自身改进，但仍慢于强FA2约10%–14%。这些都是指定合成输入的GPU resident算子结果，不是NanoKV/模型/serving加速。

后续可针对短query下较少CTA的情况试验split-KV与稳定partial-state合并；必须把scratch、额外启动与merge计入完整链路，在新的训练/冻结边界验证，不能用本轮回归事后修改旧policy。
