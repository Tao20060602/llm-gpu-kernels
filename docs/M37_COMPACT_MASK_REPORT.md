# M37 compact full-history mask diagnostic

Status: **passed**

## Scope and protocol

The public v2 `prepare_cuda_gqa_compact` entry is compared with the explicitly loaded, preserved M36 v1 native binary and reusable raw-pack plus public FA2. The v1 binary is a measurement control only. Both CUDA stages are compared against public PyTorch SDPA math in FP32; the v2 and v1 compact outputs must also match bitwise for each stage.

Eight predeclared boundary shapes run at both stages. The timing cases use T=32/96/256, history lengths (2048,64,512), and padded current-V token stride 6144. Each of five arms is captured with four forwards per graph replay, then measured in forward/reverse/forward order with three samples per arm per round. Preparation is outside timing. Every arm is checked against an independent FP32 oracle before and after timing, including graph output. Inputs are seeded synthetic BF16 tensors generated by PyTorch, not captured model activations.

## Root decision

Retain the v2 implementation as an explicit operator experiment, with no universal speed claim and no engine/default-backend change. Same-batch S2 p50 decreases by 3.52% at T96 and 1.83% at T256, and is unchanged at T32. S1 regresses by 1.84% at T32 and 0.96% at T96, while improving by 1.05% at T256. The complete-tile hypothesis therefore helps the measured S2 cases but does not establish a better general configuration. Raw-pack + FA2 remains faster at all three sizes; v2 S2 is 6.44% / 8.36% slower at T96/T256. One bounded diagnostic is sufficient to record this experiment; it is not evidence of stable fleet-wide gains.

The structural cleanup stands independently: remove compact `p_mode`, native state, `DirectP`, and shared-P reads/writes; derive shared capacity from Q plus the actual K/V stages once. Full-history validity is derived inside the existing kernel, with the original masks used for current causal tiles and partial query/key tiles. There is no caller flag, second wrapper/kernel clone, or product v1 fallback. Historical M34/M35 and the explicit benchmark control remain as experiment evidence.

Compilation reports S1/S2 at 221/231 registers per thread, both with zero stack/spills; declared dynamic shared memory remains 32,768/49,152 B. The prior v1 profile confirmed the M36 allocation threshold, but no M37 NCU capture is claimed. All 16 boundary checks and performance eager/Graph checks pass the independent FP32 SDPA math oracle and stage-matched v1 bitwise comparison.

## Reproduction and review scope

Use the repository venv and `scripts/activate-cutlass.sh` for CUDA 12.8 / GCC 14; append the FA2 overlay described in `docs/FLASH_ATTENTION_OPERATOR_ENVIRONMENT.md` for the five-arm diagnostic. Run `scripts/run_m37_compact_mask_check.py` for that diagnostic, or `python -m pytest -q tests/e2e/test_compact_attention.py` for the two public-path GPU scenarios (pytest is pinned in the `test` extra). The diagnostic requires the preserved v1 binary locally at the explicit control path above. On a fresh clone, build that control from historical commit `3338707` in a separate checkout and copy its same-named shared object there; the current loader builds only v2. The e2e scenario needs no historical binary or FA2.

The first pytest command could not start because pytest was absent; the tool was installed and the subsequent single GPU scenario run passed (2 tests). The failed command log and successful logs remain under `artifacts/m37-diagnostic/`. No GPU benchmark was repeated to select favourable samples. Build resources and the compile log are published under `results/provenance/m37-build/`; binary/cubin/full disassembly remain local.

Root review covered the full compact CUDA source and Python wrapper, profiler/NCU shell entry, both changed diagnostic runners, the new e2e scenario, and `pyproject.toml`; subsequent edits to those files were checked as diffs. README/current status and new M36 NCU/M37 design/report were read in full; changes to historical M34/M36 descriptions were checked as diffs. NCU extraction/provenance byte copies and SASS counting were delegated to Luna; root checked the reported launch/resource fields, build output and numerical/timing summaries. This is a review of this change, not of every historical operator or repository test.
