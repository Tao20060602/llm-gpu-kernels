# 首版之后的任务与时间估计

用户将当前优先级改为尽快交付可写入简历的算子项目。首版保留已完成的BF16三批
测量、W4六case单批、正确性/Graph/stream审计和已有Nsight证据；以下工作延期。
时间为基于本机和当前实现的粗估，包含处理与分析，不能保证新优化会有正收益。

| 任务 | 估计时间 | 要回答的问题 |
|---|---|---|
| W4额外两批独立进程 | 15–25分钟 | 小输入收益与大输入回归是否重复出现？ |
| W4 NCU计数器分析 | 30–60分钟 | 在线decode、scale/shared访问、权重带宽和Tensor Core供给各自如何？可能需要用户输入sudo密码 |
| Packed layout/异步decode/tile改进 | 3–8小时 | 为什么T1024比相同tile BF16还慢，能否改善而不破坏小输入收益？ |
| Group size与异常值处理 | 2–6小时 | 格式损失、scale字节和解码效率如何取舍？ |
| Down也量化并接入同域Marlin对照 | 1–2天 | 完整W4 MoE能否与成熟backend公平比较？当前混合W4/BF16无直接完整入口 |
| 完整checkpoint任务评估 | 数小时至1–2天，另加下载时间 | 层输出代理之外，任务得分实际变化是多少？ |

首版之后建议先补前两项，总计约一小时；随后根据计数器决定是否值得改变格式或
流水线。不会先扫大量tile再挑一个最好数字。原W4格式、负收益和公开数据仍保留。

NanoKV推理引擎的CPU offload、prefill/CPU gather瓶颈、TTFT与检索方案尚未取消。
它们在算子简历版交付后继续规划；改变稀疏选择算法或模型输出的取舍单独讨论，
不将这里的W4格式代理误差当成推理引擎任务得分门槛。
