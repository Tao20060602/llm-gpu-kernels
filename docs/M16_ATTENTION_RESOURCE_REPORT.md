# M16：短 query 冻结策略与历史上限验证

当前矩阵支持保留短query规则作为独立算子prototype的可用路径：36项实际自定义路径新输入的Graph p50几何平均比完整pack+FA2少22.09%，最坏慢2.17%，未超过原5%回归上限。原18项短query holdout全部更快，追加上限审计中6项T127/128略慢。不能称为所有输入更快或生产通用加速。

## 改动、搜索与判断

M15先在非空current契约下简化softmax状态。本轮固定8种token16/32 × G1/2 × key32/64组合，warps4/stages2，不改算法。seed12109，T96/384/1536 × selected257/2049；sink64/recent512/currentT。8项T65/history33/17/41及T0边界通过，48项完整候选训练全部数值正确。

候选必须全部六输入通过；每bucket两个完整Graph p50 ratio的geomean≤.95、worst≤1.05，按最小geomean/index tie选择，长复测失败FA2无次选。训练4轮AB/BA/BA/AB、8样本2replay8forward；长复测16样本4replay。强baseline复用buffer pack+未修改官方FA2公开API。

## 可用范围与下一步

独立prototype可通过FrozenResourcePolicy.load(...).prepare(q,segments).run()使用冻结选择。使用前校验provenance；改变输入shape/address需重新prepare，跨stream依赖由调用者建立。域外由FA2路径处理仍须符合四段连续BF16/Hq32/Hkv8/D128/currentT基本契约，无效输入不因policy回退自动获得支持。

NanoKV引擎默认入口没有切换，也没有任何端到端请求收益声明。本轮有限资源搜索没有让大query超过成熟FA2。后续的真实模型/请求分布、cold准备成本、并发、多GPU或系统集成需要各自实验，不能直接复用这些算子数字。
