# M9：四段 KV GQA 直接读取与 head 分组对照

正式运行全部通过。首版固定 G=1 在 T64 下比复用缓冲区拼接加官方 FA2 少约 5%–29% Graph 耗时；T≥256 的固定版本则普遍更慢。G2/G4 没有显示普遍的复用收益，全部回归保留如下。

## 输入、实现与实验边界

连续 GPU BF16 Q[T,32,128]，四段 K/V[L,8,128] 顺序为 selected/sink/recent/current；current 长度等于 T。历史全可见，current j<=query_i，kv_head=q_head//4，scale=1/sqrt(128)。不包含 RoPE、CPU gather、H2D、模型、NanoKV 或 serving。

一张 CTA 处理32个 token 和 G 个相邻 query heads，有效 BM=32G。FP32 online softmax 的 m/l/acc 跨四段更新，P 转 BF16做 value dot，FP32累加后输出BF16；不构造 packed KV、repeat KV 或临时 softmax workspace。Prepared 入口保留所有输入/output owners、编译产物与完整参数，在当前 stream 启动；T0不启动。

在线递推采用已有 FlashAttention 方法，来源见 [官方 Triton v3.3.1 教程](https://github.com/triton-lang/triton/blob/v3.3.1/python/tutorials/06-fused-attention.py)。本项目实现四段指针读取、current mask 和 GQA CTA 映射。

配置预先固定为 token_tile32/key_tile64/warps4/stages2，G1是首版，G2/G4是探索性布局对照。此轮不是holdout，没有按场景挑选最佳G形成策略。强基线每次将K/V拼入复用buffer后调用未修改官方FA2公开API；FP32 reference仅做精度检查，不用于性能对照。

## 正确性与来源

36个小型功能场景（12种输入×3种G）全部通过，覆盖空历史、T0、非整齐段/查询尾块、跨64边界、position-coded V因果边界、极端finite logits及head映射。每G另外两次原地更新Q及全部K/V，非默认stream直接调用与固定地址Graph重放均对FP32通过；恢复后输入hash一致，并断言更新hash确实改变。

全部12个性能场景也采用独立dense FP32 oracle，禁用TF32，按64 query分块避免巨大score存储。四arm在计时前、后API和Graph均检查。共243项FP32指标与36项FA2比较指标全部通过；所有指标最大RMS为0.002280815、最大normalized max为0.004807692，原阈值均保持0.008并检查finite。

## 判断与后续

G1在T64三个场景的Graph p50降低28.72%、12.82%、5.47%；较大矩阵均落后强FA2链路，不能因取消拼接就推断完整算子更快。增大G也增加有效行数和FP32状态，减少CTA数量；编译记录出现较多spill。它们是下一轮假设依据，不能在没有硬件计数器的情况下把回归归因于spill或声称KV流量减少。

下一轮另立M10候选与训练冻结边界：统一逻辑KV单循环读取四段，并比较固定的tile/warps组合，确认资源与完整链路变化。M9结果不做事后调优，NanoKV入口未接入这些候选。
